# V13：ROM 专区说明

## 一句话

在 V12 基础上新增「ROM 专区」页面（入口：玩机页 → ROM 专区），六级筛选找 ROM，
支持多选批量下载，也能**不下整包直接抠 boot / init_boot**。

---

## 一、筛选顺序

按需求指定的顺序，六级：

```
品牌 → 区域 → 版本类型 → ROM 类型 → 系列 → 机型
```

| 级别 | 说明 | 可选值 |
|---|---|---|
| 品牌 | 全部 / 具体品牌 | 一加、小米、红米、POCO、OPPO、真我、红魔、努比亚、魅族 |
| 区域 | 国行版还是什么版 | 国行版、印度版、欧洲版、全球版、北美版、俄罗斯版、印度尼西亚版、台湾版、日本版、土耳其版 |
| 版本类型 | — | 全量包、售后包 |
| ROM 类型 | 按刷机方式 | 卡刷包、线刷包、分区镜像 |
| 系列 | 自动派生 | 数字系列、Ace 系列、K 系列、Note 系列、Find 系列… |
| 机型 | 自动派生，带搜索框 | 可搜名称 / 型号 / 代号（如 PGKM10、houji） |

**级联规则**：每一级只列出「在前面所有条件下仍有可下载版本」的选项。
所以不会出现"选完发现没有结果"的情况——没有结果的选项压根不会出现在下拉里。
任一级选「全部」即不按该项过滤。

## 二、数据从哪来

**全部内置在 `assets/rom_catalog.json`，查询与筛选一步网络都不走。**
只有用户点下载时才连厂商 CDN。

| 品牌 | 来源 | 说明 |
|---|---|---|
| 一加 | 社区归档 `oneplus_archive`（GitHub release） | 130 条。文件直接来自 OEM，未修改。是**分区镜像归档**，不是完整 OTA ZIP |
| 小米 / 红米 | `mi.com` 官方帮助页原文抄录 + `xiaomirom.com` 收录的官方地址 | 26 条。印度版 MIUI 14 为主，另有 2 款 HyperOS 2/3 |
| OPPO / 真我 / 红魔 / 努比亚 / 魅族 | 机型表 | **只有机型，没有直链** |

### 关于 MIUI 和 HyperOS

小米的系统名换过，直接体现在文件名上：

```
MIUI 时代     miui_NUWAINGlobal_V14.0.10.0.TMBINXM_1fa4bb0b03_13.0.zip
              ↑ 有 miui_ 前缀

HyperOS 时代  chagall_global-ota_full-OS3.0.303.0.WPTMIXM-user-16.0-4bc308875a.zip
              ↑ 前缀取消，改成 codename-ota_full-
```

`bigota.d.miui.com` 这个域名还挂着 miui 只是历史遗留，里面放的已经是 HyperOS 包了。

所以列表里有 MIUI 字样的都是 2023 年前后的老包，新包没有。

### 为什么很多机型没有直链

不是 App 不支持，是**厂商没公开可直连地址**：

- **OPPO / 真我**：官网只给型号矩阵，不给文件 URL。真我要求用 Windows 升级工具连设备。
  ColorOS 16 起动态链接带设备态签名，10–30 分钟过期。
- **小米大部分机型**：官方 CDN 路径里那段 build hash（如 `1c8f9686ce`）是编译产物，
  任何系统属性都推不出来。**必须拿到真实文件名才能拼出 URL，不能猜**。

这类机型仍然列在清单里（能确认"我的机器被收录了"），选中后会明确说明原因。
**绝不按型号套模板生成链接**——猜出来的坏链接比"暂时没有"危害大得多。

## 三、下载

### 多选批量下载

版本列表是 ListView 多选，带「全选 / 清空」。
点「批量下载选中的版本」，勾选项逐条进队列。

**队列串行执行**，不会同时开 N 个连接把带宽打满，也不会因并发过高触发站点限流。
关掉页面不中断，进度同步到通知栏，可暂停 / 继续 / 取消。

### boot / init_boot 单独提取

两个独立按钮，走两条不同路径：

| 包类型 | 做法 |
|---|---|
| 含 `payload.bin` 的 OTA 全量包 | 走 PayloadCore 按块 Range 拉取，**不下整包**。几 GB 的包只取几十 MB 的那个分区 |
| 分区镜像归档（一加） | 包内已是解好的镜像，体积很小，直接下载解压即得 `boot.img` / `init_boot.img` / `vendor_boot.img` |

既不含 payload 又不是分区镜像的包，按钮会明确告知"只能下载整包后本地解包"，
不会让你白等。

## 四、已知限制

1. **带直链的版本只有 160 条**（一加 130 + 小米 26 + 少量），机型 502 个。
   机型全 ≠ 有包，这是数据源的现实，不是筛选 bug。

2. **一加归档不是完整 OTA**。它是从完整固件拆出的 `boot` / `firmware` / `logical` 三部分，
   `logical` 被切成多个约 2 GB 分卷。对目标分区可直接使用，
   要恢复整个 ROM 必须三样都有并按顺序合并分卷。

3. **静态归档天然滞后**。oneplus_archive 的可见版本早于当前推送版本。
   清单里的 `date` 字段标了归档日期，别把它当成"最新可用版本"。

4. **沙盒无法验证可下载性**。小米的 4 个官方镜像域名在开发环境全部返回 403
   （网络策略拦截，非直链失效），所以这些链接没经过实测。
   手机上打开应该没问题，但第一次用请先点「查询 / 复制下载链接」拿到的地址自行确认。

## 五、想加更多机型

直接编辑 `assets/rom_catalog.json`，格式很直白：

```json
{
  "brand": "小米",
  "name": "小米 14",
  "key": "houji",
  "code": "houji",
  "series": "数字系列",
  "note": "",
  "versions": [{
    "version": "OS3.0.307.0.WNCCNXM",
    "regionCode": "CN",
    "region": "国行版",
    "versionType": "全量包",
    "romType": "卡刷包",
    "android": "16",
    "url": "https://bigota.d.miui.com/.../houji-ota_full-....zip",
    "size": 0,
    "date": "",
    "note": "",
    "source": "来源说明",
    "payload": true,
    "extra": {}
  }]
}
```

`url` 留空就是"已知机型，暂无直链"。
`payload: true` 表示含 payload.bin，会启用"不下整包提取"按钮。
